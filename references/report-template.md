## 编写规范

1. **客观具体**：每个问题都要有具体文件和行号，不写空泛评价
2. **按级排序**：P0 → P1 → P2 → P3，读者从最严重的看起
3. **可操作**：每个问题都要有修复建议，不能只说"不好"不说"怎么改"
4. **量化优先**：能用数字就不用形容词（"覆盖率 85%" 比 "覆盖率较高" 好）
5. **区分事实和判断**：事实（有几处穿透）和判断（封装做得不好）分开写
